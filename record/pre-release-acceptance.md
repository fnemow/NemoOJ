## 5. 剩余风险

### 高风险（发布前必须处置）

1. **判题链路未经真实容器验证**（A10/A11）。判题的核心价值就在于此，
   策略层单测通过不等于容器内行为正确。这是当前最大的未知。
2. **限流阈值未校准**。当前值（登录 20/5min、提交 10/min、未完成 5）是经验值，
   未按真实容量测量。过高会失去保护，过低会误伤正常用户。
3. **部署编排未实测**。`docker-compose.yml` 仅通过 YAML 解析与拓扑断言，
   未真正启动过；健康检查命令、依赖等待、沙箱挂载路径一致性均未验证。

### 中风险（应在上线初期密切观察）

4. **恢复时间上界为推算值**。租约 120s + 回收周期 30s ≈ 150s，
   实测的是缩短短配置下的 3 秒恢复；默认配置下的实际恢复时间未测。
5. **RPO/RTO 未测量**。备份脚本未执行、恢复未演练，因此不能对外承诺任何具体值。
6. **存量题目补发布未执行**。V5 之后存量已发布题目在补发布前无法被提交，
   脚本已备好但需在生产执行（需用户授权）。
7. **告警规则未闭环验证**。规则表达式与指标存在性已核对，
   但未在真实 Prometheus 中验证"触发→恢复"。

### 低风险（已记录，可上线后处理）

8. 残留容器与磁盘指标未实现（需 Docker daemon / 宿主采集器）。
9. 沙箱 CPU 配额改为 CFS 后**真实性未实测**（需 Docker 环境压测确认限核生效）。
10. 多实例投递器竞争与回收器竞争未在真实多实例下演练（条件更新本身是原子的）。
