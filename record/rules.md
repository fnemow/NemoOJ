# Record 目录规则说明

## 目录结构

```
record/
  rules.md          -- 本文件：目录规则说明
  log/              -- 每次代码更改的记录
  introduction/     -- 新技术/方案的说明文档
```

## log 目录规则

**用途**：记录每一次对项目的代码更改。

**文件命名规则**：`<日期>-<目的>.md`
- 日期格式：`YYYY-MM-DD-HH-mm`（年-月-日-时-分）
- 目的：简短描述本次修改的目标，如 `fix-nacos-config`、`add-bcrypt-encryption`、`fix-judge-flow`
- 示例：`2026-05-19-14-30-fix-nacos-config.md`

**文件内容模板**：

```markdown
# <修改标题>

## 修改时间
YYYY-MM-DD HH:mm

## 修改目的
<简要说明为什么要做这次修改，解决什么问题>

## 修改内容
- <具体修改项 1>
- <具体修改项 2>
- <具体修改项 3>
```

## introduction 目录规则

**用途**：记录项目中采用的新技术或新方案的使用说明文档。

**文件命名规则**：`<技术名称>.md`
- 使用技术的通用名称，如 `BCrypt.md`、`RabbitMQ.md`、`JWT.md`
- 示例：`BCrypt.md`、`Redisson.md`、`XXL-Job.md`

**文件内容模板**：

```markdown
# <技术名称>

## 使用目的
- <为什么要引入这项技术>
- <解决什么问题>

## 使用文档
- <依赖引入方式>
- <配置步骤>
- <核心 API 使用示例>
- <注意事项>

## 横向对比
| 对比项 | 当前方案 | 替代方案 A | 替代方案 B |
|--------|----------|------------|------------|
| 优点   | ...      | ...        | ...        |
| 缺点   | ...      | ...        | ...        |

## 选择理由
<简述最终选择该技术的理由>
```

## 注意事项

1. 每次代码修改后，必须在 `log/` 下创建对应的记录文件
2. 引入新技术或替换旧技术时，必须在 `introduction/` 下创建对应的说明文档
3. 回答用户关于项目修改的问题前，先阅读本文件和记录文件以了解上下文
