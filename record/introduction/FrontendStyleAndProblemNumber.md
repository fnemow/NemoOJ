# 前端黑灰主题与自然数题号实施方案

编制日期：2026-09-20。状态：需求已确认，待实施。本文记录实施契约，不代表代码、数据库迁移或部署已完成。

## 1. 使用目的与已确认需求

- 全站以黑灰色为主，通过彩色点缀区分交互、标签和状态，不增加多套配色切换器。
- 增强 Java、C++、Python 编辑器的关键字、标识符、函数、类型等高亮。
- 题库搜索框置于页面右上角，加入放大镜图标。
- 使用从 1 开始的固定自然数题号，页面、导航链接及浏览器地址栏一并调整，例如 `/problems/1`；兼容已有长 ID 链接。
- 保留左侧导航、题目描述在左、代码编辑在右的布局，以及 ACM / 核心代码开关。

本文在主题与题号方面覆盖 `FrontendDesign.md` 中较早的浅色主题约定；其余权限、判题、草稿及版本可复现要求继续有效。实施前阅读 `record/rules.md`，代码改动后补充 `record/log/` 记录。

## 2. 当前实现与影响范围

- `nemo-frontend/src/styles/tokens.css` 使用偏蓝的深色变量，Element Plus 的部分衍生色为硬编码。
- `src/components/CodeEditor.vue` 使用 Monaco 基础 Java、Python、C++ tokenizer 和内置主题；移动端为普通 textarea。
- `src/pages/ProblemListPage.vue` 的搜索框与标签、排序并列在筛选区，题号直接展示 `row.id`。
- `src/app/router.ts` 的 `/problems/:problemId` 当前直接承载数据库 ID。
- 后端 `Question.id` 是长整型分布式 ID。创建新版本会复制出新行，并通过 `sourceQuestionId` 指向旧版本。因此公开题号必须对应逻辑题目，不能简单对每个版本行独立自增。

## 3. 视觉与交互方案

### 3.1 黑灰主题

建议初始色值如下，最终根据真实页面对比度微调：

| 用途 | 色值 |
| --- | --- |
| 页面背景 | `#121212` |
| 侧栏 | `#181818` |
| 卡片与编辑器 | `#1E1E1E` |
| 浮层、悬停 | `#282828` |
| 边框 | `#383838` |
| 主文字 / 次文字 | `#E6E6E6` / `#A3A3A3` |
| 主按钮、焦点、选中项 | `#7AA2F7` |
| 成功 / 警告 / 错误 | `#73C991` / `#E5B567` / `#F07878` |
| 辅助标签 | 紫色、青色、橙色的低饱和配色 |

集中修改设计变量与组件覆盖，清理页面中冲突的蓝黑背景。标签按稳定映射配色，状态保留文字或图标，不能只靠颜色表达。普通文本目标对比度至少 4.5:1，控件边界与焦点可辨认。同步检查表格、弹窗、下拉框、提示、登录页、管理页及加载和空状态。

### 3.2 编辑器高亮

注册统一的 Monaco 自定义深色主题：关键字紫色，字符串绿色，数字橙色，函数黄色，类型青色，普通标识符浅蓝色，注释灰色。保留已有编辑器明暗偏好的兼容处理，默认使用新的深色主题。

保留三种语言的 Monaco 官方 tokenizer，在其上叠加轻量语义标记，覆盖函数声明与调用、参数、局部变量、常量和用户类型；扫描前屏蔽注释与字符串，内容变化后短延迟刷新并限制标记数量。启用括号配对着色，并调整选区、当前行、光标、行号、建议列表和查找结果的颜色。

桌面编辑器增加本地智能补全，支持关键字、代码片段、当前文件符号、常见标准库和容器成员，以及核心代码模式的方法与参数。补全由输入、`.` 或 Ctrl+Space 触发，不在字符串和注释中主动弹出。本阶段不引入 LSP，轻量推断不承诺精准覆盖模板类型、动态调用或跨文件符号。移动端 textarea 同步黑灰样式，不加载 Monaco、补全或语义高亮；提交详情的只读编辑器复用高亮主题且不提供插入建议。

### 3.3 题库搜索

- 标题与说明位于左侧，搜索框位于标题行右侧；桌面宽度约 300–360px。
- 搜索框包含放大镜、清空按钮和可访问名称，提示“搜索题号或标题”。图标使用现有图标体系或内联 SVG，不为单个图标额外引入大型依赖。
- 标签与排序保留在列表上方；窄屏标题与搜索框换行，搜索框占满可用宽度。
- 将输入与实际查询参数分离，真正应用 300ms 防抖；查询变更回到第 1 页，保留 URL 查询参数与浏览器前进后退同步。
- 纯正整数按公开题号精确查询；其他输入按标题查询。标签继续与搜索条件组合。

## 4. 自然数题号与后端契约

### 4.1 身份与分配

新增逻辑题目编号表，建议命名 `question_identity`：自增主键 `problemNo`、唯一根题目 ID `rootQuestionId`、当前公开版本行 ID `currentQuestionId`（未发布时允许为空）、创建时间。`question` 新增可索引的 `problemNo` 字段，同一版本链共享此值；不能对版本行的该字段设置单列唯一约束。

首次创建逻辑题目时，在事务中创建题目与编号映射；新版本继承来源编号。分配使用数据库自增及唯一约束，禁止运行时使用 `MAX + 1`。编号从 1 开始，分配后永久固定；删除、失败事务或未发布草稿可能产生空号，不进行重排或复用。

发布版本时，锁定逻辑题目映射并原子更新当前公开版本指针，校验来源与版本次序，防止较旧分支覆盖较新发布版本。题库每个逻辑题目展示一次，详情默认读取当前公开版本。旧版本及提交快照仍保留；当前公开版本删除后置为不可公开访问，不自动回退到旧版本。统计首期继续使用当前版本现有统计口径，不在此次改动中重算历史数据。

### 4.2 数据迁移

新增下一序号迁移，当前预计为 `V9__public_problem_number.sql`，实施时核对最新迁移编号，不修改 V1–V8。

1. 备份题目、版本、提交相关表，检查 `sourceQuestionId` 是否存在孤儿、环或分支冲突。
2. 沿来源关系识别逻辑题目根节点；遇到不能可靠归组的数据先输出报告并解决，不静默猜测。
3. 按根题目的 `createTime, id` 稳定排序，从 1 分配编号，再回填各版本行。
4. 为每组选择最高已发布版本作为当前公开版本；并列版本或异常链须先解决。
5. 校验每行映射、根节点唯一性和发布指针，设置后续自增起点及必要索引。
6. 按现有迁移框架记录执行结果，验证重复执行不会重复分配编号。

### 4.3 API

- 题目列表、详情、管理员详情及提交关联题目摘要增加 `problemNo`；保留原 `id` / `questionId` 作为内部身份。
- 公共列表请求增加可选 `problemNo` 精确过滤字段，并确保分页总数按逻辑题目计算。
- 新增按题号解析公开题目的入口，建议 `GET /api/question/get/vo/by-number?problemNo=1`。返回原有详情结构与新增题号字段；未发布、删除或不存在题目遵循现有错误信封与可见性规则。
- 现有按 ID 详情接口用于兼容旧链接和版本相关流程，继续执行权限校验。
- 模板、语言能力、提交及草稿仍使用解析后的实际 `questionId`、版本和执行模式。不能把公开题号直接传入原有 ID 参数。

## 5. 导航与旧链接兼容

- 新的题库行链接、题目标题链接、面包屑以及提交记录中的题目入口统一使用 `/problems/{problemNo}`；可见题号统一为 `1`、`2` 等，提交编号不改。
- 路由参数调整为表达公开编号的名称；统一封装题目链接生成方法，避免各页面自行拼接长 ID。
- 对现有部署的长 ID 链接建立明确兼容判定：先校验已存量 ID 的范围与公开编号范围。兼容规则基于已验证范围或映射，不使用 JavaScript Number 解析长 ID，也不无条件在两个命名空间之间回退。
- 普通旧题目入口解析到逻辑题号后使用 `router.replace` 跳转，保留安全查询参数。历史提交复制回编辑器时增加明确的版本上下文，按原版本 ID、语言和执行模式恢复，不因规范化网址而加载不匹配的模板。
- 不移动已有按实际 ID、语言、模式分隔的草稿键；公开编号解析成功后再加载草稿，避免跨题或跨版本覆盖。
- 刷新自然数深层路由可访问；未知编号显示 404，权限错误不转成公开详情。

## 6. 实施顺序与交付

1. **后端与迁移**：确认版本链数据，落地编号映射、回填、分配与发布事务、公开列表和详情契约；补充并发和版本测试。
2. **前端编号**：更新 API 类型、路由解析、链接生成、题号搜索、列表/详情/提交关联展示，并完成旧链接及草稿兼容。
3. **主题与搜索布局**：统一黑灰 token、彩色点缀、组件状态及右上角搜索框。
4. **编辑器**：落地自定义主题和必要词法规则，检查三种语言、两种执行模式与只读编辑器。
5. **验证与部署**：先迁移和部署兼容后端，再部署前端；在虚拟机完成真实接口和浏览器联调，记录结果。

交付包含源码、数据库迁移、接口说明、变更记录及验证结果。本文阶段只交付实施文档。

## 7. 验收标准

- 页面主体为中性黑灰，彩色只用于强调与信息分类；左导航和左右做题布局正常。
- 搜索位于桌面右上角，放大镜可见；输入防抖、清空、分页重置、URL 状态及窄屏换行可用。
- Java / Python / C++ 示例中的关键字、字符串、数字、函数、类型、标识符和括号符合高亮规则；多行注释与字符串不发生明显误着色。
- 题号在排序、筛选、分页和刷新后保持不变；并发创建不重复，同题新版本继承编号，删除后不重排。
- 新题号网址、旧 ID 链接、题目入口及提交记录跳转均可用；历史版本恢复、模式切换和草稿互不覆盖。
- 发布更新后题库不出现同一逻辑题目的多个版本；未发布和已删除数据不会通过编号入口泄露。
- 前端 type-check、lint、build 通过；针对编号和查询规则补充有意义的单测，浏览器覆盖搜索、旧链接、版本与模式切换。
- 后端验证迁移回填、并发分配、版本发布指针、可见性、分页与历史提交兼容；在真实环境确认题号、模板和提交链路。

## 8. 方案对比与选择理由

| 方案 | 优点 | 局限 |
| --- | --- | --- |
| 前端按列表下标显示题号 | 修改少 | 排序和筛选后变化，无法稳定导航 |
| 每个题目版本行独立自增编号 | 数据结构简单 | 同一题目新版本会改号 |
| 独立逻辑题目编号映射（采用） | 编号稳定，支持版本和旧链接兼容 | 需要迁移及发布事务改造 |

选择独立映射是为了匹配现有“新版本创建新行”的模型，同时保留原 ID、判题快照和草稿的稳定性。视觉方面沿用现有 Vue、Element Plus 与 Monaco，不更换组件库。
