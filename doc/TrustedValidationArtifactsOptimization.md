# 已审核私人题型预验证与完整结果复用

实施日期：2026-10-14。

## 改动与能力范围

对平台代码中已审核的 18 个常用题型及 3 个红黑树难度题型，建立固定验收数据包，每包保留 20 组覆盖边界及典型情况的输入。不同用户的私人题仍使用独立记录和访问权限；同一已审核题型共用验收输入。题型本身的算法及参数语义保持固定，展示标题可按需求变化。自由生成的其他算法题仍走现有生成与完整验证流程。

部署包生成脚本从仓库维护的参考实现产生服务端白名单。模型不能向白名单写入内容，也不能仅凭 `templateId` 声明获得缓存权限。审核匹配包含核心签名、模式、资源限制、原始用例及输出占位、三语言参考实现、独立 Python 校验解、协议与模板版本；题面描述另外校验，只有展示标题可变化。

完整缓存指纹还包含实时可用的三语言不可变镜像摘要、运行时信息，以及当前实际生成的七份执行计划（独立 Python 校验解及三语言 ACM/FUNCTION），包括 Runner/SDK 文件、编译源文件、输入与资源限制。语言或模式未开放、镜像不可用、镜像没有固定摘要时不能命中缓存。Runner、代码、输入或限制改变时重新验证。

仅完整验证成功、独立校验解通过且六种语言模式全部通过的结果可以复用。缓存包含原始验证证据、参考实现及答案；读取时检查摘要和结果结构，返回独立的数据副本。失败结果、部分验证结果和自由生成代码不复用完整证明。缓存故障、缺失、损坏或过期均回退到完整验证。

## 保存与运维

判题服务独占 `/srv/nemo-oj/trusted-validation-cache`，挂载到 `/var/lib/nemo-validation`。目录仅服务用户可读写，不挂载到执行用户程序的沙箱。条目有效期 7 天，最多 64 条，每条最多 1 MB；以临时文件和原子替换写入。缓存是可重建的验证产物，不是数据库备份。

低基数指标 `nemo.ai.private.validation.artifacts` 记录 miss、hit、validated。命中结果包含 `completeProofReused=true`，当前阶段耗时为 0；原证明耗时保存在 `validatedCombinationMillis`，用于区分历史验证与当前执行。

开关 `AI_TRUSTED_VALIDATION_CACHE_ENABLED=false` 可关闭完整缓存。部署叠加层为 `deploy/compose.trusted-artifacts.yml`。原镜像保留用于回退。预验证脚本只在未完成提交和 AI 任务均为 0 时启动下一包，并使用现有后台验证通道。预验证不会发布题目，也不会调用模型。

预验证默认从本次报告续跑。再次检查过期缓存或更新数据包时加 `--refresh`，例如 `python3 trusted_artifact_prewarm.py /home/ubuntu/nemo-artifacts-20261014 --refresh`；此时重新检查所有数据包，已有合法证明会快速复用，缺失或失效条目会重验。

## 实测结果
