# 题目级自定义数据结构实施与验收

更新日期：2026-10-14。

## 实施结果

平台支持在题目的 `ProblemSpec.dataStructures` 中声明节点类。核心代码参数和返回类型使用 `node<ClassName>`，Runner 自动补充 Java、Python、C++ 类定义、构造函数和编解码。用户只需编写 `Solution`，不再因为全局模板缺少某种节点类而被拒绝生成。

这是受限的数据描述能力，不接受任意 SDK、模型生成的类方法或第三方依赖。自定义节点类仅对所属题目生效；既有链表、二叉树和普通数组题继续沿用原有路径。

## 结构契约

以下声明可以表达带颜色和父指针的树：

```json
{
  "className": "Solution",
  "methodName": "check",
  "parameters": [{"name": "start", "type": "node<RBNode>"}],
  "returnType": "boolean",
  "dataStructures": [{
    "name": "RBNode",
    "fields": [
      {"name": "value", "type": "int"},
      {"name": "color", "type": "int"},
      {"name": "left", "type": "ref"},
      {"name": "right", "type": "ref"},
      {"name": "parent", "type": "ref"}
    ]
  }]
}
```

`ref` 是同类节点引用，`ref[]` 是同类引用列表。它们在核心代码中是对象或指针，不能当成整数编号。节点关系允许父指针、循环、自环和共享对象。

| 限制 | 规则 |
| --- | --- |
| 类数量 | 每题最多 4 个 |
| 字段数量 | 每类 1～12 个，名称不重复 |
| 字段类型 | int、long、double、boolean、string、ref、ref[] |
| 类名称 | 大写 ASCII 字母开头，随后字母或数字，最多 40 字符 |
| 字段名称 | 跨语言标识符，禁止关键字及平台运行时保留名 |
| 单个节点图 | 最多 200 个节点 |
| 单个引用列表 | 最多 32 项 |
| 字符串 | 最多 200 个字符，不含换行 |
| 单组生成输入 | 沿用现有 12000 字符上限，因此各项最大值不能无限叠加 |
| 引用目标 | 首版只引用同一类；不支持跨类引用 |

数值须在对应整数范围内；double 必须有限；布尔值不能用 0/1 冒充。描述中不包含可执行代码。构造函数提供无参和字段参数版本；Python 也支持字段关键字。

## 输入、输出与 Runner

核心代码模式的公开样例使用 JSON：

```json
{"start":{"root":0,"nodes":[
  {"value":8,"color":0,"left":1,"right":-1,"parent":-1},
  {"value":3,"color":1,"left":-1,"right":-1,"parent":0}
]}}
```

整图为空时使用 `{"start":null}`。引用值为节点编号，`-1` 表示空引用。根编号必须有效，每条记录具有且仅具有声明字段。

Runner 分两步构造对象：先创建所有节点，再连接引用。因此父指针和循环不会导致递归构造失败。输出按字段声明顺序进行广度遍历，以对象身份去重；根重新编号为 0，仅输出根可以到达的节点，保留共享和循环关系。

Java 生成的辅助类合并到平台的 `Runner.java`，继续遵守沙箱原有的文件布局。Python 在加载用户模块前注入节点类，支持参数注解。C++ 在包含用户的 `solution.hpp` 前声明节点类；标准 JSON Runner 与现有轻量 C++ 分离编译路径都已适配。

ACM 模式沿用 `CANONICAL_LINES_V1`：空节点单行 `-1`；非空节点先写节点数量、根编号，再按节点顺序及字段声明顺序写数据。`ref` 使用整数编码，`ref[]` 使用整数数组编码。现有标量和数组协议保持不变。

## AI 生成与验证

生成提示和严格输出 schema 都支持自定义声明。题目规格冻结后，将声明一并传入跨语言实现和局部修复阶段，不允许实现擅自定义不在规格中的节点类。

真实验收发现模型容易在输入记录中附带无法从根到达的节点。生成准备阶段现在会：

1. 先检查全部记录的字段、类型、边界及引用合法性。
2. 从根按声明字段顺序遍历，删除无法到达的记录。
3. 重排编号并同步更新引用，形成唯一的根对象图表示。
4. 用规范化后的同一份数据生成核心代码和 ACM 用例。

这种处理不改变核心函数可访问的对象；不修复越界引用、错误类型、字段缺失或逻辑错误。原输入对象也不会被修改。后端仍要求提交的规格与节点数据严格有效。

自定义题目仍需 20 组用例、两个独立 Python 算法及 Java/Python/C++ × ACM/FUNCTION 六组合沙箱验证，不能直接借用可信题型的完整证明缓存。日志只记录有限失败类别，不记录模型原文、源码或用例值。

## 前端与接口

- 核心代码题面显示“平台节点定义”，列出字段及引用含义。
- Java 模板使用类名，C++ 模板使用类指针；Python 直接使用参数。
- 编辑器补全提供声明的类及直接节点参数的字段，支持 C++ `->`。
- 平台已提供的类不允许通过模板按钮重复插入。
- 私人题接口单独返回最多两个非隐藏核心代码样例，隐藏用例和参考实现仍不公开。
- 公开题目的 DTO 保留结构描述；私人题仍按拥有者校验读取和提交权限。
- 不新增数据库表或迁移，结构定义保存在原有 JSON 规格中；不改变判题结果协议。

## 部署和边界

判题服务、问题服务、Agent 采用现有镜像的窄范围补丁，保留无关类和配置。问题服务补入 Gson 依赖。每次服务更新前检查无未完成任务；前端先发布全部资源，再原子切换入口文件，不重启代理，并保留旧散列资源。

保留原镜像用于回滚，本轮未创建数据备份。注册继续关闭，配额、限流、模型配置和沙箱隔离保持原有规则。

本轮主要扩充生成能力并减少无效输入导致的失败，不承诺未知题型的固定生成时间或成功率。需要跨类引用、数组值字段、对象构造操作序列或复杂第三方库时，应继续扩充受限契约与对应编解码，不能直接执行模型生成的任意 SDK。
