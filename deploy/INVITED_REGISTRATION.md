# 邀请注册

当前云端处于备案浏览模式，登录、注册页面及公开认证接口暂时关闭，`REGISTRATION_ENABLED=false`。以下流程在明确恢复认证后使用；详情见 [备案浏览模式](FILING_MODE.md)。新站管理员初始化必须在关闭注册之前完成，初始化脚本不会自动打开注册。

所有新用户必须持有管理员提供的一次性邀请码。现有账号继续正常登录，邀请码不会授予管理员或 VIP 权限。

## 管理员操作

登录 `nemo_admin`，进入 **用户管理 → 注册邀请**。

1. 设置有效期：1～720 小时，默认 72 小时；备注可选，最多 120 字。
2. 点击“生成邀请码”，复制后交给受邀用户。明文仅在生成成功的弹窗中显示一次，关闭后无法从列表找回；丢失时撤销并重新生成。
3. 受邀用户在注册页面填写邀请码、账号和密码。注册成功立即消耗邀请码；账号重复、密码校验失败等失败注册不会消耗。
4. 列表可查看可使用、已使用、已过期、已撤销状态以及使用者 ID。未使用且未过期的邀请码可撤销。

有效期由数据库 UTC 时间判定，页面按北京时间显示。数据库仅保存随机 192 位邀请码的 SHA-256 摘要。注册时锁定邀请记录，用户创建和邀请消费在同一事务内完成；并发使用同一个邀请码最多成功一次。现有注册限流和 CSRF 校验继续生效。

## 部署和初始化

先通过现有 `deploy/migration/apply_migrations.sh` 应用 `V18__registration_invitation.sql`，再更新用户服务与前端。没有关闭邀请码校验的环境开关，也没有公开的管理员注册接口。

全新部署使用 `deploy/bootstrap_admin.sh`。脚本通过主机数据库创建 15 分钟有效的一次性邀请，再调用同一个注册接口、提升新账号并验证登录和管理员权限；密码由终端隐藏输入。账号已存在时终止，不覆盖角色或密码。若初始化中途失败，短期邀请自动过期；若账号已创建但提升失败，必须由主机维护人员核对账号后恢复，不重复执行以覆盖账号。

管理员 API（仍须登录、管理员角色及写操作 CSRF）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/user/invitations/admin?current=1&pageSize=20` | 分页查看记录，不返回明文或摘要 |
| POST | `/api/user/invitations/admin` | `{validityHours, note}` 创建，返回一次性明文 |
| POST | `/api/user/invitations/admin/{id}/revoke` | 撤销尚未使用且未过期的邀请 |
| POST | `/api/user/register` | 原注册参数增加必填 `invitationCode` |

隔离环境的全链路验收脚本需通过 `ACCEPTANCE_INVITATION_CODE` 提供新的一次性邀请，每轮使用不同邀请。不得把邀请、密码或会话凭据写进版本库或验收日志。

## 云端版本和回退

2026-09-30 腾讯云用户服务镜像为 `nemo-oj/user-service:invite-20260930`，迁移记录为 V18；备份存放于服务器 `/srv/nemo-oj/deploy/backups/invitation-20260930/`，包含原服务、前端、数据库及仅主机可读的 Compose 环境配置。

V18 是新增表，不删除既有用户。发生故障时优先修复或临时阻断注册接口；直接回退旧用户服务会恢复无邀请码注册，不能作为保持邀请限制的回退方案。前端回退也必须与要求邀请码的新接口兼容。不要删除邀请审计表或覆盖现有用户数据。
